# Урок 2 Разработка агента

Добро пожаловать на второй урок курса «Создание AI-агента с нуля до продакшена»!

В этом уроке мы рассмотрим:

- Инструменты для создания наших AI-агентов
  
- Инструкции по настройке наших ресурсов для разработки

- Лучшие практики разработки AI-агентов
  
- Пошаговый разбор кода создания наших AI-агентов
  
Начнем с обзора инструментов, которые мы будем использовать для создания наших AI-агентов.

## Инструменты и инструкции по настройке

### Microsoft Foundry

Для доступа к большим языковым моделям (LLM) мы будем использовать [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry). Использование Foundry связано с затратами, поэтому, если у вас еще нет доступа, обязательно следуйте инструкциям по настройке аккаунта.

### Модели OpenAI

Примеры кода агентов в этом курсе настроены на использование моделей OpenAI через [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry).

Используйте это руководство, чтобы узнать, как развернуть модель с помощью Foundry: [Развертывание моделей Microsoft Foundry в портале Foundry](https://learn.microsoft.com/azure/ai-foundry/foundry-models/how-to/deploy-foundry-models?view=foundry-classic)

Выберите одну модель из серии GPT-5 (например, `gpt-5.1`) для этого курса. Избегайте устаревших моделей, таких как GPT-4o и GPT-4.1, срок службы которых заканчивается в 2026 году.

### Microsoft Agent Framework

Как упоминалось ранее, мы будем использовать [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) для создания и оркестровки наших AI-агентов.

Вам потребуется **Python 3.12 или новее**. Чтобы установить Microsoft Agent Framework и другие необходимые пакеты, выполните следующую команду, находясь в корневой папке этого проекта:

```bash
pip install -r requirements.txt
```

### Аутентификация в Azure

Агенты аутентифицируются в Microsoft Foundry, используя ваши учетные данные Azure CLI
(`AzureCliCredential`), поэтому необходимо войти в систему перед запуском любого примера:

```bash
az login
# Если у вас несколько подписок, выберите ту, которая связана с вашим проектом Foundry:
az account set --subscription "<your-subscription-id>"
```

Убедитесь, что ваша учетная запись имеет роль **Azure AI User** (или эквивалент) в проекте Foundry,
чтобы иметь возможность вызывать API моделей и агентов.

### Настройка переменных в .env

Для запуска примеров кода этого курса вам нужно создать файл `.env` в корневой директории проекта.

Для удобства вы можете скопировать предоставленный файл `.env.example`:

```bash
cp .env.example .env
``` 

Затем заполните две переменные, которые используют агенты (класс `FoundryChatClient` автоматически их подхватывает):


|----------|------------|------------------|
| `FOUNDRY_PROJECT_ENDPOINT` | Ваш конечный адрес **проекта** Foundry, заканчивающийся на `/api/projects/<project>` | Портал Foundry → ваш проект → **Обзор** → *Endpoints* |
| `FOUNDRY_MODEL` | Имя развертывания модели, на которой работают агенты (например, `gpt-5.1`) | Портал Foundry → **Models + endpoints** |




который хранится в Microsoft Foundry **векторном хранилище**. Создайте его один раз и скопируйте
ID, который он выведет, в ваш `.env` как `VECTOR_STORE_ID` (запускайте из корневой папки репозитория,
чтобы он подхватил ваш `.env`):

```bash
python lesson-2-agent-development/setup_vector_store.py
```

### Запуск примера

Каждый агент запускает свой локальный DevUI. Например:

```bash
python lesson-2-agent-development/employee-search-agent.py
```

Затем откройте выведенный URL `http://localhost:<port>` в браузере для общения с агентом.

## Агенты в этом уроке

Каждый пример — это отдельный агент, построенный с использованием Microsoft Agent Framework. Вместе они
реализуют сценарии, которые вы разработали в [Уроке 1](../lesson-1-agent-design/README.md):

| Пример | Сценарий из Урока 1 | Используемый инструмент | Порт |
|--------|-------------------|-----------|------|
| `employee-search-agent.py` | Сценарий 1 — Поиск сотрудников | Поиск файлов на Foundry через векторное хранилище | 8090 |
| `task-recommendation-agent.py` | Сценарий 2 — Рекомендация задач | Сервер **GitHub MCP** (инструмент MCP в облаке) | 8095 |
| `azure-learning-agent.py` | Сценарий 3 — Помощник по коду (исследование) | Сервер **Microsoft Learn MCP** (инструмент MCP в облаке) | 8092 |
| `coding-agent.py` | Сценарий 3 — Помощник по коду (кодирование) | **Code Interpreter** | 8093 |
| `learning-recommendation-agent.py` | Поддерживающий агент | Learn MCP + логическое рассуждение | 8091 |
| `agent-orchestration.py` | Связывает сценарии вместе | Оркестрация передачи управления между агентами | 8094 |

> **Примечание по агенту рекомендации задач.** `task-recommendation-agent.py` требует
> `GITHUB_PERSONAL_ACCESS_TOKEN` в вашем `.env` (создайте его на
> <https://github.com/settings/personal-access-tokens/new>). Агент читает недавнюю
> активность разработчика на GitHub и рекомендует 1–3 открытых задачи, соответствующих критериям — это именно дизайн Сценария 2.
> Это единственный пример, который обращается к GitHub; остальные требуют только ваш проект Foundry.
