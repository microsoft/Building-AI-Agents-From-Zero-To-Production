# Урок 2 Розробка агента

Ласкаво просимо на другий урок курсу "Побудова AI агента від нуля до продакшену"!

У цьому уроці ми розглянемо:

- Інструменти для створення наших AI агентів
  
- Інструкції з налаштування наших ресурсів розробки

- Кращі практики розробки AI агентів
  
- Крок за кроком огляд коду для створення наших AI агентів
  
Почнемо з огляду інструментів, які ми використовуватимемо для створення наших AI агентів.

## Інструменти та інструкції з налаштування

### Microsoft Foundry

Для доступу до великих мовних моделей (LLMs) ми будемо використовувати [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry). Використання Foundry пов’язане з витратами, тому, будь ласка, дотримуйтесь інструкцій щодо налаштування облікового запису, якщо ви ще не маєте доступу.

### Моделі OpenAI

Приклади коду агента у цьому курсі налаштовані на використання моделей OpenAI через [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry).

Використовуйте цей посібник, щоб дізнатись, як розгорнути модель за допомогою Foundry: [Deploy Microsoft Foundry Models in the Foundry portal](https://learn.microsoft.com/azure/ai-foundry/foundry-models/how-to/deploy-foundry-models?view=foundry-classic)

Виберіть одну модель серії GPT-5 (наприклад, `gpt-5.1`) для цього курсу. Уникайте застарілих моделей, таких як GPT-4o та GPT-4.1, термін підтримки яких закінчується у 2026 році.

### Microsoft Agent Framework

Як згадувалося раніше, ми будемо використовувати [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) для створення й оркестрації наших AI агентів.

Вам знадобиться **Python 3.12 або пізнішої версії**. Щоб встановити Microsoft Agent Framework та інші необхідні пакети, виконайте наступну команду у кореневому каталозі цього проєкту:

```bash
pip install -r requirements.txt
```

### Аутентифікація в Azure

Агенти аутентифікуються у Microsoft Foundry, використовуючи ваші облікові дані Azure CLI
(`AzureCliCredential`), тому необхідно увійти в систему перед запуском будь-якого прикладу:

```bash
az login
# Якщо у вас є більше ніж одна підписка, виберіть ту, що містить ваш проект Foundry:
az account set --subscription "<your-subscription-id>"
```

Переконайтеся, що ваш акаунт має роль **Azure AI User** (або еквівалент) у проєкті Foundry,
щоб мати змогу звертатися до API моделей та агентів.

### Налаштування змінних .env

Щоб запускати приклади коду цього курсу, потрібно створити файл `.env` у корені цього проєкту.

Щоб спростити завдання, ви можете скопіювати наданий файл `.env.example`:

```bash
cp .env.example .env
``` 

Потім заповніть дві змінні, які читають агенти (їх підхоплює `FoundryChatClient`
автоматично):

| Змінна | Що це | Де знайти |
|----------|------------|------------------|
| `FOUNDRY_PROJECT_ENDPOINT` | Кінцева точка вашого Foundry **проєкту**, що завершується `/api/projects/<project>` | Портал Foundry → ваш проєкт → **Огляд** → *Endpoints* |
| `FOUNDRY_MODEL` | Ім’я розгортання моделі, на якій працюють ваші агенти (наприклад `gpt-5.1`) | Портал Foundry → **Models + endpoints** |

### Створення векторного сховища працівників

Один з прикладів — **Employee Search Agent** — здійснює пошук у довіднику працівників, що зберігається у
векторному сховищі Microsoft Foundry. Створіть його один раз і скопіюйте ID, що виводиться, у ваш `.env`
як `VECTOR_STORE_ID` (запустіть з кореневого каталогу репозиторію, щоб було прочитано ваш `.env`):

```bash
python lesson-2-agent-development/setup_vector_store.py
```

### Запуск прикладу

Кожен агент запускає власний локальний DevUI. Наприклад:

```bash
python lesson-2-agent-development/employee-search-agent.py
```

Потім відкрийте надруковану URL `http://localhost:<port>` у вашому браузері, щоб спілкуватися з агентом.

## Агенти в цьому уроці

Кожен приклад — це автономний агент, створений за допомогою Microsoft Agent Framework. Разом вони
реалізують сценарії, які ви розробили в [Уроці 1](../lesson-1-agent-design/README.md):

| Приклад | Сценарій уроку 1 | Використаний інструмент | Порт |
|--------|-------------------|-----------|------|
| `employee-search-agent.py` | Сценарій 1 — Пошук працівника | Пошук у файлах через векторне сховище, розміщене у Foundry | 8090 |
| `task-recommendation-agent.py` | Сценарій 2 — Рекомендації завдань | Сервер **GitHub MCP** (розміщений інструмент MCP) | 8095 |
| `azure-learning-agent.py` | Сценарій 3 — Помічник коду (дослідження) | Сервер **Microsoft Learn MCP** (розміщений інструмент MCP) | 8092 |
| `coding-agent.py` | Сценарій 3 — Помічник коду (безпосередньо кодування) | **Code Interpreter** | 8093 |
| `learning-recommendation-agent.py` | Підтримуючий агент | Learn MCP + логіка | 8091 |
| `agent-orchestration.py` | Об’єднує сценарії | Оркестрація передачі між агентами (multi-agent **handoff**) | 8094 |

> **Примітка щодо агента Рекомендації завдань.** `task-recommendation-agent.py` потребує
> `GITHUB_PERSONAL_ACCESS_TOKEN` у вашому `.env` (створіть його за адресою
> <https://github.com/settings/personal-access-tokens/new>). Він зчитує недавні
> активності розробника на GitHub і рекомендує 1–3 відкриті issues, що відповідають — точно як у сценарії 2.
> Це єдиний приклад, що звертається до GitHub; інші потребують лише ваш проєкт Foundry.
